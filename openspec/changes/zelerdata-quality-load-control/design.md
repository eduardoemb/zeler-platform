# Design: ZelerData Quality Load Control

`items.quality_probe` stores `status`, `checked_at`, `next_probe_at` and the Mercado Libre item's `last_updated` observed during the probe. Only a quality 404 records `not_generated` and a one-hour retry time. A changed item bypasses that wait. A successful quality response records `available`. Other errors retain existing retry behavior and do not advance the probe. The quality projection and its source timestamp are preserved if no probe was performed.

The recovery worker treats `quality_projection:transient:performance_not_generated` as an optional field gap when completing a 20-item acquisition chunk. The formula still returns `DATA_UNAVAILABLE` for missing quality. The API filters quality recovery IDs by probe due time. Admission then serializes on the existing seller revision document and subtracts IDs already present in pending/running item jobs. This works for both catalog and small explicit-ID requests and retains the 20-job seller cap.

For the four legacy overlapping jobs, the operator command first emits only a fingerprint and counts. Execution requires that exact fingerprint, seller ID, a drained worker, and an expired or absent active lease. A Mongo transaction marks old jobs `failed` with `superseded_by_item_reconciliation`, preserves their documents and successful chunks, and creates one job for the union of unfinished IDs not already completed by another job. The transaction serializes against admission and conflicts with concurrent claim/checkpoint writes. It refuses changed snapshots and more than 10,000 remaining IDs. No old job is deleted.

Rollout order: save validator and image rollback identities; stop the `sheets-worker` service, which briefly pauses Sheets event consumption; apply only the additive `items` validator; deploy the compatible Sheets API and stage the worker image; preview and explicitly authorize legacy reconciliation in a one-shot container; start the worker; verify item jobs, quality 404 rate, request volume, memory, queue health and formula result at 0/30/60/90 minutes. If the worker or API regresses, stop recovery and restore compatible images. Keep the additive validator and persisted probe/job evidence; never restore an image that rejects the new field.
